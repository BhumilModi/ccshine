# Rail Plan Section Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When the Tide rail is docked, draw the full plan as a section pinned to the rail's bottom and shrink the band's plan to one header line.

**Architecture:** The plan's drawing moves from `features/tasks.tsx` into a pure `hooks/planview.tsx` that both the band and the rail call with plain data. The band asks `fitBand` for the header only while the rail owns the plan; the rail budgets its turn rows around a plan section capped at half its height.

**Tech Stack:** TypeScript/TSX Claude Code plugin hooks, `claude-code/testing` test kit, `./verify.sh`.

**Spec:** `docs/superpowers/specs/2026-10-06-rail-plan-design.md`

## Global Constraints

- `$` is never passed across an import (the plugin loader refuses the module); planview takes plain data, resolved components and callbacks only.
- Render hooks never write state; loads and writes happen in event hooks or `onPress` handlers.
- Atoms are declared in each file that reads them: `atom({ plugin: 'tidepool', key: '<key>' } as const, <default>)`.
- Rail owns the plan exactly when the band's existing `railDocked($, e)` is true (rail option on, fullscreen, 110+ columns, `tidepool-rail` placed).
- Plan section height: at most `Math.floor(scroll.bodyRows / 2)` rows unless `planAll` is true.
- Finished plan lingers `AGENT_LINGER_MS` (30s), then folds away in band and rail.
- No `Co-Authored-By` or AI attribution in commits. No `git push`.

## Review Focus

- Rail docked but no tasks, only a running shell: the rail shows the shell section alone; the band shows no plan line and keeps the dock.
- Rail very short (`bodyRows` under 10): the plan section still shows its header and the running task; tool rows drop to `N earlier`.
- Show all with a plan taller than the rail: every line draws and the pane scrolls; nothing throws.
- Rail undocked mid-plan (window narrowed): the band returns to the full fitted plan on its next draw.
- Finished plan with the rail docked: both the rail section and the band line fold away after 30s.

### Task 1: Extract the plan's drawing into `hooks/planview.tsx`

Behaviour-preserving move. Existing band tests are the safety net.

**Files:**
- Create: `hooks/planview.tsx`
- Modify: `hooks/features/tasks.tsx` (remove `Line`, `planLines`, the header/line/shell drawing now in planview; `planBand` and `shellSection` call planview)
- Test: `tests/planview.test.tsx`

**Interfaces:**
- Produces, all exported from `hooks/planview.tsx`:
  - `type PlanUi = { Box; Text; Button }` — the three components from `$.ui.resolve(e)` (type them as `ReturnType<EngineInterface['ui']['resolve']>` picks).
  - `type PlanData = { tasks: PlanTask[]; agents: AgentRow[]; shells: ShellRow[]; tails: Record<string, string>; shellHistory: Record<string, number[]>; planHistory: number[]; now: number; all: boolean }` — `tails` maps a job's `outputFile` to its last line.
  - `type Line` and `planLines(tasks, agents, now, all): { lines: Line[]; focus: number }` — moved unchanged from tasks.tsx.
  - `planHeader(ui: PlanUi, C: Palette, d: PlanData, o: { surface: string; columns: number; toggle?: { hidden: number; onPress: () => void } }): RenderElement` — the powerline header; the `▾ show all` / `▴ fewer` Button (`key="all"`) only when `toggle` is given and `d.all || toggle.hidden > 0`.
  - `planBody(ui, C, d: PlanData, room: number): { rows: RenderElement[]; hidden: number }` — window + markers within `room` rows (uses `windowLines`); `hidden` = all-lines count (with `all: true`) minus lines shown, for the toggle.
  - `shellBody(ui, C, d: PlanData, tails: boolean): RenderElement[]` — `shell` label, one row per shell, output line under a running background row when `tails` and `d.tails[outputFile]` exist.
  - `planWanted(d: PlanData): { plan: number; shell: number; tails: number; focus: boolean }` — the ask numbers `fitBand` and the rail need (`plan` = lines − 1, capped at `MAX_TASK_ROWS` = 8 unless `all`).
- `Palette` is `ReturnType<typeof palette>` from `hooks/theme`.

  - `planWanted` for 3 top-level tasks (second `in_progress`, with one sub-item) returns `{ plan: 3, shell: 0, tails: 0, focus: true }` with `all: false`.
  - `planWanted` with one running background shell whose `outputFile` is in `tails` returns `shell: 2, tails: 1`.
- [ ] **Step 2: Run** `claude plugin test . 2>&1 | grep -E "planview|^ [0-9]+ (pass|fail)"` — expect the file to fail to load (module missing).
- [ ] **Step 3: Create `hooks/planview.tsx`** by moving `Line`, `planLines`, the header segments, the line `draw` function and the shell row drawing out of `features/tasks.tsx`; add `planWanted`. Move `MAX_TASK_ROWS`, `MAX_AGENT_ROWS` with them. Tail reads stay in tasks.tsx (`tailLine` uses `$`): it now fills a `tails` record before calling planview.
- [ ] **Step 4: Rewire `planBand`/`shellSection` in `features/tasks.tsx`** to build a `PlanData` and call `planWanted`, `planHeader`, `planBody`, `shellBody`. `shellSection` and the in-file `draw` go away.
