# Tidepool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebrand ccshine as Tidepool, then move tool calls, agents and background jobs out of the chat into a per-turn waterfall rail.

**Architecture:** Phase 1 is a pure rename plus a one-time store migration. Phase 2 adds pure model code (`hooks/rail.ts`, `hooks/jobs.ts`, `span()` in `hooks/theme.ts`), extends the tracker (`features/track.tsx`) with turn spans, call targets and background jobs, and adds one feature module (`features/rail.tsx`) that draws the `Pane`. `features/tools.tsx` turns tool rows into one anchor line per turn.

**Tech Stack:** Claude Code mod API (`claude-code`, `claude-code/testing`), TypeScript/TSX, `claude plugin test`, `./verify.sh`.

**Spec:** `docs/superpowers/specs/2026-10-05-tidepool-design.md`

## Global Constraints

- Requires Claude Code 2.1.288+ (unchanged from ccshine).
- No new dependencies.
- Every atom uses `plugin: 'tidepool'` once Task 1 lands; `types/index.d.ts` `PluginState` key `'tidepool'`.
- Colours come from `palette()` in `hooks/theme.ts` only; no literal colours in features.
- Bar glyphs: heavy `━` fill, `╸` half cell at the end, `╺` half cell at the start, thin `─` track in `C.track`. No `█`, no `▕▏`.
- Commit messages: plain conventional commits written as the owner. No `Co-Authored-By`, no AI attribution of any kind. Never `git push`.
- Known simplifications get a `// ponytail:` comment naming the ceiling.
- Done means `./verify.sh` exits 0.

## Review Focus

1. A turn with no tool calls: no anchor line in the chat; the rail shows the turn header and `no tools this turn`. (Task 6, Task 7)
2. A turn stopped with Esc: its span still gets `endedAt`, running calls stop growing, the anchor shows the counts so far. (Task 4)
3. `/clear` while a background shell runs: spans, jobs and selection reset; a later task notification for the old id is ignored, not an error. (Task 4)
4. The window shrinks from fullscreen to normal mode mid-turn: placement flips to `inline`, the rail shows the compact live view, and the tasks band brings its agent rows back. (Task 6, Task 7)
5. Calls that started before a hot reload (no timing): they appear in the rail without a bar and never crash the render. (Task 3)

### Task 3: Bar span helper and pure rail model

**Files:**
- Modify: `hooks/theme.ts` (add `span`)
- Create: `hooks/rail.ts`
- Modify: `types/index.d.ts` (types below)
- Test: `tests/rail.test.ts`

**Interfaces:**
- Consumes: `CallTiming` gains `target?: string; added?: number; removed?: number; failed?: true` (written by Task 4; read here). `PlanAgent` gains `callId?: string` (Task 4).
- Produces (all in `types/index.d.ts` unless noted):
  - `TurnSpan = { turnId: string; startedAt: number; endedAt?: number; aborted?: true; ctxStart?: number; ctxEnd?: number; costStart?: number; costEnd?: number }`
  - `Job = { id: string; callId: string; startedAt: number; endedAt?: number; status: 'running' | 'done' | 'error' | 'killed' }`
  - `RailRow = { id: string; tool: string; target: string; from?: number; to?: number; over: boolean; running: boolean; failed: boolean; kind: 'tool' | 'agent' | 'job'; ms?: number; added?: number; removed?: number; children?: number }`. `from` and `to` are fractions 0..1 of the window; both are absent when the call has no timing.
  - `RailSummary = { ms: number; tools: number; agents: number; ctx?: [number, number]; cost?: number; files: { path: string; added: number; removed: number }[]; failures: { label: string; times: number }[] }`
  - `hooks/theme.ts`: `span(from: number, to: number, width: number): { before: string; filled: string; after: string }`
  - `hooks/rail.ts`: `turnWindow(span: TurnSpan, now: number): { start: number; end: number }`, `railRows(calls: Record<string, CallTiming>, agents: PlanAgent[], jobs: Job[], span: TurnSpan, now: number): RailRow[]`, `railSummary(rows: RailRow[], calls: Record<string, CallTiming>, span: TurnSpan, now: number): RailSummary`, `turnOfCall(spans: TurnSpan[], at: number): TurnSpan | undefined`, `showBars(bodyColumns: number): boolean`.

- [ ] **Step 1: Write the failing tests** (`tests/rail.test.ts`):
  - `span draws heavy line on track with half cells`: `span(0, 0.5, 4)` gives `{ before: '', filled: '━━', after: '──' }`. `span(0.125, 0.5, 4)` gives `filled` starting with `╺`. `span(0, 0.375, 4)` gives `filled` `━╸`. A zero-length span at 0.5 still fills one half cell.

  - `railSummary`: files aggregate `added`/`removed` per path; failures with the same `tool + target` fold to `times: 2`; ctx pair comes from the span.
  - `showBars(39)` is false; `showBars(40)` is true.
